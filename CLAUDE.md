# watchlist-builder

Static page on GitHub Pages (yariktrade.github.io/watchlist-builder): live USDT/USDC symbol lists of crypto exchanges for TradingView watchlist import.

- Two static pages, no build, no dependencies: `index.html` (the builder) and `log.html` (the changes log, linked from the settings panel). Shared code: `base.css` (palette, chips, buttons) and `shared.js` (theme before first paint, exchange display names). The only data source is the public `scanner.tradingview.com/crypto/scan`, queried anonymously from the browser (CORS allowed, no cookies). Never use a TradingView account or the TradingView MCP for this project.
- Rows: every exchange in the response, tagged CEX/DEX by TradingView's `centralization` field. `KNOWN` only names CEXes and sets their order; DEX ids are split into protocol / version / chain for display. Rows and columns with nothing under the current choice are hidden.
- Columns: Spot, Perps, TradFi (dated futures are not requested: few under USDT/USDC, and they expire). TradFi is a derivative with an empty `base_currency`. On 2026-10-22 this matched the exchanges' own classification for 1537 of 1540 symbols. TradingView gives no TradFi subtype, so "Split TradFi by ticker" (a setting, off by default) classifies by the underlying, guessed from the ticker: Stocks = one company (single-stock leveraged funds included); Indices = index contracts and funds on a basket or index (broad, sector, country, bond, volatility; crypto funds too); Metals / Commodities = contracts and funds on them; FX = currency pairs. Funds are a known list (`FUNDS`); an unlisted fund falls back to Stocks.
- Output: `EXCHANGE:SYMBOL`, comma-separated, at most 1000 entries per list. "Together" (default) packs all cells into one list, split into parts; "Separate" gives one per cell. Copy gives the plain list; the .txt adds `###Exchange Market` sections (on by default, headers count toward the limit).
- Layout: pinned header (name; Venue and Quote chips; gear with settings). Column headers stick under it via `--head-h`. Settings: TradFi split, stale filter, Listed period, list mode, sections, theme. Venue, quote and settings persist in localStorage `wb-settings`; the cell selection does not.
- "Listed" (setting: All / 1d / 7d / 30d, default All): keeps only symbols whose first bar on TradingView (`first_bar_time`, about the listing date) is within the period, so the usual select / Copy / Download gives new listings per exchange and market.
- Stale filter (setting, on by default): hides symbols TradingView has had no price for in 7+ days (`STALE_DAYS`; a dead feed such as CoinEx, or a delisted pair TradingView has not dropped yet).
- Changes log: `.github/workflows/snapshot.yml` runs `scripts/snapshot.py` daily at 00:07 UTC (also by hand via workflow_dispatch). It stores the symbol set in `data/symbols.json` and appends added and removed symbols per day to `data/log.json`; `data/exchanges.json` tags each exchange CEX/DEX. `log.html` (back arrow to the builder) shows one row per added or removed symbol; the column headers open the filters (period; exchanges, multi-select with CEX/DEX groups and search; ticker and quote; added/removed), remembered in localStorage `wb-log`; Copy takes the filtered symbols. It refuses to log when the response shrinks below 80% of the last one (outage guard). Entries marked `first-bar` were backfilled at the start from TradingView's first-bar dates (additions only). The bot commits to `main`, so `git pull --rebase` before pushing.
- Publish only through the GitHub account `yariktrade`, never the owner's personal account.
- Verify: `./check.sh` must print `PASS` (live requests, headless Chrome, selects the whole table).
